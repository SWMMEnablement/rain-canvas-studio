- The storm calculator lives in `supabase/functions/_shared/rainfallPatterns.ts` and is used by both the app (via `src/lib/rainfallPatterns.ts` re-export) and the storm-api function; never fork it — so app and API results always match.
- Patterns with identical hyetographs are merged via `PATTERN_ALIASES` in `supabase/functions/_shared/patternCatalog.ts`; aliases stay accepted in links/API but are hidden from the catalogue and sitemap.
- The app's predefined catalogue must match `CANONICAL_PATTERN_IDS` exactly; derive visible counts and hero lists from `stormPatterns`, excluding the separate Custom editor option, to keep app/API totals consistent.
- `generateRainfallData` is a guarded wrapper over `generateRainfallDataDetailed`: it must always return finite, non-negative values that conserve depth, and the detailed form reports any fallback with a plain reason that the storm check, export headers and API show — so silent shape changes are never hidden from users.
- Only patterns benchmarked against published ordinates in `methodFidelity.test.ts` may be High confidence; anything using typical parameters is Medium at most and states its `approximation` — so labels never overstate fidelity.
- The wizard snaps the time step (`fitTimeStep`) so duration is a whole number of intervals — fixed-interval exports assume full intervals.
- Storm file text formats (CSV, SWMM, HEC gage) are built in `src/lib/stormFileExports.ts` / `src/lib/hecHmsExport.ts` and must load back through `src/lib/rainfallParsers.ts`; `exportReimport.test.ts` round-trips every format — so exports and imports never drift apart.
- Per-pattern source notes and confidence levels come only from `src/lib/patternProvenance.ts`; unlisted patterns default to low confidence — confidence is raised only with a named source.
- The equation explorer reads its numbers from `generateRainfallData` via `src/lib/equationExplorer.ts`, never from separate formulas — so explanation and generated storm cannot disagree.
- Linked engineering calculations (unit transfers, Modified Puls, unit-hydrograph convolution, LID accounting) live in `src/lib/hydrologyCalcs.ts` with tests; components only call them — so the hydraulics stay testable.
- Tab panels stay mounted after first open (`src/components/ui/tabs.tsx`, opt out with `keepMounted={false}`) — so switching tabs never discards user work.
- The Storm Generator publishes the active storm (`src/lib/activeStorm.ts`) via `onActiveStormChange`; other tabs read it instead of keeping their own storm defaults — so every tab analyses the same storm.
- The Changes tab reads `src/lib/changelog.ts`; add a release entry there when shipping notable changes — so the history stays current.
